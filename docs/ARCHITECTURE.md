# Архитектура

Пакет `com.vladosiwe.solostatus`. Каждая система вынесена в свой пакет, интеграции изолированы.

| Система | Пакет / класс | Назначение |
|---|---|---|
| PlayerData | `data/PlayerData`, `data/Hunter` | Профиль охотника, сериализация, версия формата, миграции |
| Persistence | `registry/ModAttachments` | Data attachment NeoForge (`copyOnDeath`), сохраняется вместе с игроком |
| LevelSystem | `level/LevelSystem` | Опыт, уровни, очки, Преодоление предела |
| AttributeSystem | `stats/AttributeSystem`, `stats/StatFormulas` | Формулы характеристик, временные модификаторы атрибутов |
| ClassSystem / SpecializationSystem | `clazz/*` | Классы, специализации, Испытание смены пути |
| SkillSystem | `skill/SkillSystem` | Изучение, улучшение, слоты, применение, сброс |
| SkillUnlockSystem | `skill/SkillUnlockSystem` | Адаптивное пробуждение по условиям |
| SkillTreeSystem | `skill/Skills`, `skill/SkillDef`, `skill/Req` | Реестр навыков, требования, позиции в дереве |
| Эффекты навыков | `skill/SkillEffects`, `skill/SkillFx`, `skill/Scheduler` | Механики навыков (только сервер) |
| CombatSystem | `combat/CombatEvents`, `combat/Threat`, `combat/WeaponClassifier` | Анализ боя, анти-фарм, типы оружия |
| MasterySystem | `mastery/*` | Мастерство оружия и школ магии |
| WeaponQualitySystem | `quality/*` | Data component качества, лут, подсказки |
| HunterRankSystem | `rank/*` | Очки силы и ранги |
| AchievementSystem | `achievement/*` | Достижения, скрытые достижения, награды |
| Networking | `network/*` | Пакеты, синхронизация, осмотр |
| StatusScreen / HUD | `client/*` | Голографический интерфейс (только клиент) |
| Configuration | `config/SoloConfig` | Серверный баланс + клиентские настройки |
| EpicFightCompatibility | `compat/epicfight` | Изолированная интеграция |
| IronSpellsCompatibility | `compat/ironsspells` | Изолированная интеграция |
| VoiceIntegration | `voice/VoiceCommands` | Распознавание командных фраз (текст / будущий STT) |

## Клиент и сервер

- Весь код в `client/` помечен `@EventBusSubscriber(value = Dist.CLIENT)` или вызывается только из клиентских обработчиков пакетов. На выделенном сервере он не загружается.
- Клиентские обработчики пакетов вызываются из тел лямбд в `ModNetwork`. Класс `ClientPayloadHandler` разрешается JVM только при выполнении, а на сервере этого не происходит.
- Интеграции не импортируют классы чужих модов: используются id реестров (атрибуты, типы урона) и отражение с проверкой наличия.

## Сеть и безопасность

- Клиент → сервер: только **запросы** (распределить очко, выбрать класс, изучить навык, применить слот, сброс, осмотр). Сервер проверяет каждое значение: наличие очков, пределы характеристик, класс и условия навыка, перезарядку, энергию, наличие Сферы, дистанцию и видимость для осмотра.
- Сервер → клиент: собственный профиль игрока целиком (только ему), энергия, уведомления, отфильтрованный результат осмотра. Профили других игроков никому не рассылаются.
- Защита от повторных наград: id достижения добавляется в набор до выдачи награды, набор сохраняется. Навыки хранятся в map, поэтому дублей быть не может. Выбор класса и специализации однократен.
- Синхронизация: важные изменения отправляются в конце тика, мелкие (счётчики, опыт мастерства) раз в секунду.

## Сохранение

- `AttachmentType.serializable(...).copyOnDeath()`: данные сохраняются с игроком и переживают выход, перезапуск и смерть.
- Поле `v` хранит версию формата, `PlayerData.migrate` предназначен для будущих миграций. Чтение защищено: значения ограничиваются допустимыми диапазонами, при ошибке используются значения по умолчанию, сервер не падает.
- Навыки — часть профиля, а не предметы. Их нельзя выбросить, передать, положить в сундук или потерять.

## Производительность

- Анализ боя событийный (урон, блок, смерть, крафт, дроп), без проверок каждый кадр.
- Тик игрока: синхронизация раз в тик только при изменениях; регенерация энергии, проверка пробуждений, достижений и ранга раз в секунду и только если что-то изменилось; качество оружия в руке раз в 2 секунды; дистанция бега и аура раз в 5 секунд.
- Многоударные навыки используют серверный `Scheduler`, без отдельных потоков.
